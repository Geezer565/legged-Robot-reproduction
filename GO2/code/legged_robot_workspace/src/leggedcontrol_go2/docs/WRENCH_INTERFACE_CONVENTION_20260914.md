# Go2 六维力接口统一约定（2026-09-14）

## 唯一定义

所有方法、控制器、记录文件和绘图统一使用：

- 顺序：`[Fx, Fy, Fz, Tx, Ty, Tz]`；
- 坐标轴：world；
- 力矩参考点：`go2::base` 原点；
- `externalWrenchEstimate`：与真实外部扰动同号；
- `requiredControlCorrection`：与外部扰动反号。

因此 Gazebo 在 `go2::base` 原点施加纯 `Fy` 时，记录和绘图中的目标为
`[0, Fy, 0, 0, 0, 0]`。

## 各环节的转换

1. Gazebo 每次读取 `go2::base` 的世界坐标位置，并在该点施加 world-frame wrench。
2. 质心动量平衡天然得到绕质心的力矩残差。进入学习器前转换为绕 base 原点：
   `tau_base = tau_com + (p_com - p_base) x F`。
3. V3 使用一般形式的 `B_w^T E_c`。由于参考点不是质心，不能使用
   `B_w=(1/m)[I6;0]` 的逐轴简化式。
4. 预测模型收到 base-origin wrench 后转换回质心力矩：
   `tau_com = tau_base - (p_com - p_base) x F`。
5. 全身控制和公共接触力分配器都用脚端相对 base 原点的位置构造六维力矩。
6. 诊断记录和绘图保留 base-origin wrench，不再把分配器输出误写成质心力矩。

## 本次修复

修复前，公共接触力分配器单独以质心为参考，而其输入实际是绕 base 原点的
补偿指令。横向力因此在最后一步丢失了 base 与质心之间的力臂力矩。

修复后，分配器显式接收世界坐标中的参考点和脚端位置，并统一以
`go2::base` 原点计算和返回六维力。该入口由 V3、V4 和所有迁移的对比方法共用。

## 验证要求

每次修改六维力接口后至少检查：

- 平移整个机器人后，同一相对接触布局的分配结果不变；
- 纯横向力不会凭空产生未请求的 base-origin 力矩；
- 施扰记录中的参考点等于当次 `go2::base` 原点；
- V3 必须保留一般 `B_w^T E_c`，除非以后整套接口明确改为质心参考点；
- 五种方法必须共用同一分配入口和限制条件。
