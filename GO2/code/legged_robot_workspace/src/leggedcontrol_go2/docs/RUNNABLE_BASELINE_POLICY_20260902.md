## 结论

今后的 MyRBF 修改统一从 `codex/myrbf-v5a-repeat-gate` 开始。

- 当前开发基线：`ef736884dff0ec802d08369d1725c43ef69a1088`
- 正式实验源码锁：`f5dab9da29d91e53ba59840670831ed732fca07f`

正式实验源码锁用于追溯 2026-09-01 的实验，不能直接改写。新设计应新建分支、新建结果目录，并保留与旧结果的对应关系。

## 为什么选择这个版本

这个版本不是孤立的算法文件，而是已经接入现有 Go2 仿真控制链路的完整版本，包含：

1. MyRBF 估计模块；
2. 面向控制器的接入层；
3. 与 `LeggedController` 的调用关系；
4. 统一启动文件和参数；
5. 批量实验、结果校验和报告生成；
6. 对异常终止、日志归属和源码一致性的检查。

因此，后续新增多地形、负重或新子网时，应沿用这一条链路，不再从仅能离线运行的旧脚本另起一套。

## 后续修改范围

优先修改以下位置：

- `legged_controllers/` 中的 MyRBF 估计与控制接入；
- 对应的参数和启动文件；
- `legged_controllers/test/` 中与新行为对应的检查；
- `scripts/` 中的实验计划和结果核对；
- 新建的 `results/<实验名称_日期>/`；
- 与新版本对应的设计和验证文档。

不要直接修改历史 `results/` 目录中的正式原始记录，也不要把编译目录和个人临时文件提交到仓库。

## 每次修改后的最低检查

1. 先运行 MyRBF 自动检查；
2. 确认批量实验计划数量和参数正确；
3. 核对报告中的日志、源码版本和结果文件是否一一对应；
4. 先做无扰动短时 Gazebo 验证；
5. 再逐步增加扰动、负重和地形复杂度；
6. 任一安全条件触发后，先查明原因，再继续下一档实验。

## 实机边界

当前仓库能确认的是 Gazebo 仿真链路。真实 Go2 的硬件接口仍被隔离，也没有可核验的实机启动记录和实验数据。

因此，上实机前至少要另行完成：通信检查、急停验证、力矩和速度限幅、站立保护、小幅运动测试以及人工接管流程。通过这些检查后，才能把同一套算法接到真实机器人。
